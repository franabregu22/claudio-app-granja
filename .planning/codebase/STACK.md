# Technology Stack Documentation

## Overview
Claudio App Granja is a PWA (Progressive Web App) for farm management with real-time financial tracking, built on Vite + React frontend, TypeScript Netlify Functions backend, and PostgreSQL database via Supabase.

---

### Framework & Language
- **Framework**: Vite 8.2.0 (build tool) with React 19.2.8
- **Language**: TypeScript 6.0.2 (strict mode)
- **Type Checking**: tsconfig.app.json and tsconfig.node.json

- **CSS Framework**: Tailwind CSS 4.3.3

## Backend Stack

### Runtime & Framework
- **Functions**: Netlify Functions (serverless)
- **Language**: TypeScript
- **Runtime**: Node.js (version not specified in .nvmrc)
- **Handler Pattern**: @netlify/functions Handler interface

### Database
- **Primary Database**: PostgreSQL (via Supabase)
- **Database Client**: @supabase/supabase-js 2.112.2
- **Connection**: Supabase service role key (server-side) and anon key (client-side)

### Server-Side Libraries
- **Crypto**: Node.js built-in crypto module (HMAC-SHA256 for webhook validation)
- **Fetch API**: Node.js built-in (for MercadoPago API calls)

### Scheduled Functions
- **Scheduling**: Netlify Scheduled Functions (cron)
- **Primary Job**: sync-mercadopago-releases (daily at 02:00 UTC)

### API Integration Points
- **Supabase**: Service role auth for backend operations
- **MercadoPago**: OAuth 2.0 with client credentials (access token via Bearer auth)

## Database Schema (Supabase)

### Key Tables
1. **mp_source_record** — Raw, versioned data (CSV, API, webhook)
   - source_type: report | api | webhook
   - payload_hash: SHA256 deduplication
   - raw_data: JSONB storage

2. **mp_financial_movement** — Normalized financial movements
   - movement_class: payment_in | payment_out | yield | transfer_in | transfer_out | unclassified
   - settlement_amount, transaction_amount, tax_amount
   - transaction_date, settlement_date

3. **mp_movement_source_link** — Many-to-one relationship
   - Links source records to financial movements

4. **ledger_entry** — Impact on account balance
   - balance_impact, category, account_id

5. **account_balance** — Daily calculated balances
   - opening_balance, observed_balance_mp, balance_date

6. **perfiles** — User profiles and roles
   - role-based access control

7. **webhook_events** — Audit log for webhook processing
   - event_type, event_id, request_id, resource_type, data, processed flag

### Indexes
- Full-text and composite indexes on source_type, source_external_id, transaction_date
- Processing status and payload_hash indexes for efficient querying

## Notes

- **No Next.js**: This is a Vite SPA, not a Next.js framework
- **No explicit ORM**: Raw Supabase queries via @supabase/supabase-js
- **No API gateway**: Direct Supabase client from frontend (anon key scoped)
- **Scheduled tasks**: Netlify Cron Functions (not GitHub Actions)
- **PWA-first**: Standalone app mode with offline support via Service Worker
